## 1. 30 秒看懂它做什么

```
目标钱包在 Polymarket 下单
        │
        ▼
系统检测到（轮询 2 秒 + WebSocket 实时推送）
        │
        ▼
交易进入策略管道（你自由组合的 N 个策略依次处理）
        │
        ▼
风控检查（单笔上限 / 单市场上限 / 每日笔数）
        │
        ▼
组合分配检查（多钱包分散度控制）
        │
        ▼
执行下单（paper 模拟 或 live 真实）
        │
        ▼
记入虚拟持仓账本（按真实盘口价建仓/平仓）
        │
        ▼
按真实市价盯市 → 浮动盈亏实时更新
        │
        ▼
落库 + 前端实时刷新 + 可选通知推送
```

**核心能力**：

| 能力 | 说明 |
|---|---|
| 实时监测 | 轮询（默认 2 秒）+ WebSocket Market Channel 双通道 |
| 自动跟单 | 检测到目标钱包交易后全自动走完上述链路 |
| 10 种策略 | 过滤 / 变换 / 风控 / 执行四类，可拖拽自由组合成管道 |
| 双层执行 | paper 模拟练手（真实价盯市结算），live 真实下单 |
| 回测调优 | 用历史数据验证，自动扫描最优参数 |
| 多钱包分散 | 按权重分配资金，防止过度集中在单一钱包 |
| 虚拟持仓盯市 | 模拟资金按 Polymarket 真实市价实时计算浮动/已实现盈亏 |
| 通知推送 | Telegram / 钉钉 / 企业微信 / 邮件 |

## 2. 启动服务

### 最快路径（推荐，什么都不用装）

项目已内置 Python（`Python312/` 目录），无需安装任何东西：

1. 双击 **`1-start-service-bundled.bat`**
2. 看到 `Uvicorn running on http://0.0.0.0:8765` 即启动成功
3. 浏览器打开 **<http://localhost:8765>**

> ⚠️ 这个黑窗口不能关，关了服务就停了。最小化即可。

### 停服务

双击 **`2-stop-service.bat`**，或直接关掉黑窗口。

### 其他启动方式

| 场景 | 命令 |
|---|---|
| 用系统 Python | 双击 `1-start-service.bat` |
| 手动命令行 | `Python312\python.exe run.py --host 0.0.0.0 --port 8765` |
| 换端口 | 命令行加 `--port 9000` |
| 装依赖到系统 Python | 双击 `0-install-deps.bat` |

## 3. 五步配好自动跟单

### 第 1 步：添加监控钱包

进入 **👛 钱包监控** 面板。

**方式 A：手动添加**
- 在 `钱包地址` 输入框粘贴 `0x...` 开头的地址
- `备注名` 可填一个有辨识度的名字（如 `HomeRunHazard`）
- 点 **添加**

**方式 B：从排行榜一键导入巨鲸**
- 点 **加载** 拉取 Polymarket 盈利排行榜
- 勾选感兴趣的钱包
- 点 **导入选中**

> 你此前提供的两个可直接用：
> - HomeRunHazard `0x5268527977f700f9bf9b6d5cd843859e4e70135d`
> - BreakTheBank `0xf0318c32136c2db7fec88b84869aee6a1106c80c`

添加后确保钱包的启用开关是**打开**状态。

### 第 2 步：创建策略管道

进入 **⚙️ 策略工坊** 面板。

1. 点 **➕ 新建**
2. 在 `管道名称` 填个名字，例如 `真实-大额跟单`
3. 从左侧策略列表**拖拽**策略到右侧编辑区，按顺序排列
4. 点某个策略可以改它的参数
5. 点 **💾 保存管道**

**新手推荐组合**（按顺序拖这三个）：

| 顺序 | 策略 | 作用 | 建议参数 |
|---|---|---|---|
| 1 | 金额过滤（SIZE_FILTER） | 只跟单金额达标的交易 | `最小金额 = 100` |
| 2 | 比例跟单（PROPORTIONAL） | 按比例缩小下单量 | `比例系数 = 0.1` |
| 3 | 镜像跟单（MIRROR） | 复制方向与数量，生成下单信号 | 无参数 |

> **为什么必须以 MIRROR 或 REVERSE 结尾？**
> 前两类策略只是在「加工」交易，只有执行类策略（MIRROR/REVERSE）才会真正产出下单信号。没有它，管道不会产生任何跟单。

### 第 3 步：启用管道

在策略工坊的管道列表里，确认你的管道状态是**启用**（绿色）。停用状态的管道不会参与跟单。

### 第 4 步：确认在模拟模式

进入 **🔧 设置** 面板，确认 `执行模式` 选的是 **paper（模拟）**，点 **应用**。

> 首次使用务必保持 paper，熟悉后再考虑切 live。

### 第 5 步：观察结果

- **🏠 仪表盘**：今日交易 / 信号 / 执行数、总盈亏、实时延迟、WS 连接状态
- **📈 交易流**：目标钱包的每一笔捕获到的交易
- **🎯 执行记录**：系统实际产生的跟单下单记录（含状态、成交价、错误信息）
- **💼 虚拟持仓**：当前持仓与按真实市价盯市的盈亏（详见[第 5 章](#5-模拟盘的钱是怎么算的虚拟持仓盯市)）

到此，自动检测 + 自动跟单已经在跑了。目标钱包一下单，系统会在 2 秒内捕获并完成跟单。

## 4. 一键自检：不等真实交易也能验证

真实交易什么时候发生不确定，所以系统内置了**模拟交易注入**功能——你主动造一笔交易，让它走完整的跟单链路。

在 **🏠 仪表盘** 底部找到 **🧪 链路自检** 卡片：

1. 卡片会列出三项前置条件，每项前有状态灯：
   - 🟢 监控钱包（至少 1 个）
   - 🟢 启用中的策略管道（至少 1 条）
   - 🟢 模拟模式（必须为 paper）
2. 三项全绿后，填好 `模拟金额` 和 `成交价格`
3. 点 **⚡ 注入一笔模拟交易**
4. 点 **查看执行记录 →**，如果看到一条新的 `FILLED` 记录，说明全链路打通

> **金额怎么填？**
> 输入框填的是**源交易**的金额（不是你的下单金额）。最终下单金额 = 源金额 × 策略缩放比例。
> 例如策略里 `比例系数 = 0.1`，填 200 USDC，实际下单约 20 USDC。
> 同时注意风控的 `单笔上限`（默认 100 USDC），超过会被拒绝并在执行记录里写明原因。

**自检结果怎么读**：

| 现象 | 含义 | 处理 |
|---|---|---|
| 执行记录出现 `FILLED` | ✅ 全链路正常 | 无 |
| 执行记录出现 `FAILED` + 「单笔金额 X 超过上限 100」 | 风控拦截 | 调大风控上限，或调小比例系数 |
| 执行记录**没有**新记录 | 交易被策略过滤了 | 检查金额过滤阈值是否过高 |
| 提示「模拟注入仅在 paper 模式可用」 | 当前是 live 模式 | 到设置里切回 paper |

## 5. 模拟盘的钱是怎么算的？虚拟持仓盯市

模拟模式（paper）**不是拍脑袋估算盈亏**，而是：真实市场数据 + 虚拟资金 + 实盘价结算。

### 一句话理解

> 信号是真的、价格是真的、结算是真的 —— 只有**钱是假的**。

### 四个环节分别取什么价

| 环节 | 取的价 | 说明 |
|---|:---:|---|
| 发现信号 | 目标钱包的**真实成交** | 从 Polymarket Data API 轮询捕获 |
| 建仓成交价 | CLOB **真实盘口价** | 买入取 `ask`（卖一），卖出取 `bid`（买一） |
| 持有期估值 | **真实市价**盯市 | 多头按 `bid` 估值，空头按 `ask` 估值；取不到时退用中间价 |
| 平仓结算 | **真实成交价** 配对 | 已实现盈亏 =（成交价 − 加权均价）× 平仓量 |

### 怎么看：💼 虚拟持仓面板

在**左侧导航栏**找到 **💼 虚拟持仓**（在 🧺 组合跟单 下方，倒数第二个），点进去：

顶部四张指标卡：

| 卡片 | 含义 |
|---|---|
| 未平仓 | 当前还持有的标的数 |
| 已实现盈亏 | **已经平仓**落袋的部分 |
| 浮动盈亏 | 还持仓、随行情实时变化的部分 |
| 总盈亏 | 已实现 + 浮动 |

下方是持仓明细表，每行是一个标的：市场名称、来源钱包、方向（多头/空头）、数量、均价、**现价**、市值、已实现、浮动、总盈亏、**计价来源**。

- `计价来源` 显示 `bid` = 用真实买一价估值；`ask` = 用卖一价；`midpoint` = 用中间价；`unavailable` = 取不到真实价（此时浮动盈亏显示为按成本价计算，不会乱编）
- 面板右上角有**自动刷新开关**，打开后每 **15 秒**拉一次真实价（只在停留在这个面板时才请求，切走就停）
- 点 **重置** 可以清空全部虚拟持仓（重新开始记账，不影响监控钱包和策略配置）

### 一个具体例子

假设目标钱包买了某市场 200 USDC，你的策略是 1:1 跟：

1. 系统捕获这笔真实交易 → 生成跟单信号
2. 去 CLOB 查真实盘口，假设 `ask = 0.67` → **按 0.67 建仓 200 份**（不是按目标钱包的成交价）
3. 行情涨了，`bid` 变成 0.70 → 浮动盈亏 =（0.70 − 0.67）× 200 = **+6 USDC**
4. 目标钱包卖出，你跟着卖，此时 `bid = 0.72` → 已实现 =（0.72 − 0.67）× 200 = **+10 USDC**

全程没有一个数字是估算出来的。

### 和「执行记录」面板的区别

| 面板 | 看什么 |
|---|---|
| 🎯 执行记录 | **每一笔**下单动作（时间、方向、成交价、数量、状态） |
| 💼 虚拟持仓 | **当前**持仓和累计盈亏（盯市视角） |

两个都看才完整：执行记录是流水，虚拟持仓是账户。

## 6. 10 种策略与自由组合

策略分四类，管道中**按你拖入的顺序依次执行**，前一个的输出是后一个的输入，任一环节返回「过滤」则整条链终止。

### 过滤类（FILTER）——决定跟不跟

| 策略 | 参数 | 说明 |
|---|---|---|
| **金额过滤** SIZE_FILTER | `最小金额` 默认 50 USDC | 源交易金额低于阈值直接不跟 |
| **市场过滤** MARKET_FILTER | `模式`（白名单/黑名单）、`市场 slug 列表`、`标签列表`、`最小成交量` | 只跟指定市场，或排除指定市场 |

### 变换类（TRANSFORM）——决定跟多少

| 策略 | 参数 | 说明 |
|---|---|---|
| **比例跟单** PROPORTIONAL | `比例系数` 默认 1.0 | 下单量 = 源数量 × 系数 |
| **固定金额** FIXED_AMOUNT | `固定金额` 默认 100 USDC | 不管源交易多大，每单固定投这么多（数量 = 金额 ÷ 价格） |
| **价格偏移** PRICE_OFFSET | `偏移量` 默认 0.01、`方向`（buy_up/sell_down/auto） | 挂单价格比源价格高/低一点，追求更好成交价 |
| **延迟执行** DELAYED | `延迟秒数` 默认 0 | 延迟 N 秒再下单，避开瞬时冲击 |

### 风控类（RISK）——控制敞口

| 策略 | 参数 | 说明 |
|---|---|---|
| **仓位上限** POSITION_CAP | `单市场最大` 默认 1000、`总最大` 默认 10000 | 同一市场/总仓位的累计上限 |
| **止盈止损** STOP_LOSS | `止损比例` 默认 0.1、`止盈比例` 默认 0.2 | 触发后反向平仓 |

### 执行类（EXECUTION）——产出下单信号

| 策略 | 参数 | 说明 |
|---|---|---|
| **镜像跟单** MIRROR | 无 | 完全复制源交易的方向与数量 |
| **反向跟单** REVERSE | 无 | 做反向操作（源买我卖、源卖我买） |

### 常见组合配方

| 场景 | 组合 |
|---|---|
| **保守小额练手** | 金额过滤(100) → 比例跟单(0.1) → 镜像跟单 |
| **只跟大单** | 金额过滤(1000) → 比例跟单(0.5) → 镜像跟单 |
| **固定预算** | 市场过滤(白名单) → 固定金额(50) → 镜像跟单 |
| **反向对冲** | 金额过滤(200) → 反向跟单 |
| **严格风控** | 金额过滤(100) → 比例跟单(0.2) → 仓位上限(500/5000) → 止盈止损(0.1/0.2) → 镜像跟单 |
| **慢一步进场** | 金额过滤(100) → 延迟执行(30) → 价格偏移(-0.01) → 镜像跟单 |

## 7. 回测：先用历史数据验证策略

进入 **🧪 策略回测** 面板。

1. 选择 `钱包`（要回测哪个目标钱包的历史交易）
2. 选择 `策略管道`（要验证哪条管道）
3. 设置 `初始资金`（默认 1000）
4. 设置 `起止时间`
5. 可选：`滑点`（默认 1%）、`最小金额`、`单市场最大仓位`
6. 点 **▶️ 运行回测**

看什么：

- **总盈亏 / 收益率**：这个策略在这段历史上赚不赚
- **胜率**：盈利单占比
- **盈亏比**：平均盈利 ÷ 平均亏损
- **最大回撤**：最惨时亏了多少
- **信号数**：样本够不够（太少说明参数太严，结论不可信）

点 **🔁 对比全部钱包** 可以横向比较多个钱包哪个更值得跟。

## 8. 策略调优：自动找最优参数

进入 **🧬 策略调优** 面板。

1. 选择钱包和管道
2. 设置初始资金
3. 点 **▶️ 开始扫描**

系统会自动枚举管道中每个策略的可选参数组合（上限 60 组），逐组跑回测，按综合评分排序：

```
评分 = 总盈亏 × (1 + 胜率) × 盈亏比/(1+盈亏比) × (1 − min(最大回撤/初始资金, 1))
```

这个公式同时奖励**赚钱**、**高胜率**、**高盈亏比**，并惩罚**大回撤**。

排在最前面的组合，点一下即可**一键写回**该管道的参数。
不满意可以点 **↩️ 全部恢复默认**。

## 9. 绩效分析

进入 **📈 绩效分析** 面板，四个维度：

| 维度 | 看什么 |
|---|---|
| **总览** | 累计盈亏、胜率、盈亏比、最大回撤、手续费 |
| **按钱包** | 哪个被跟的钱包贡献最多/最坑 |
| **按策略** | 哪条管道表现最好 |
| **按市场** | 哪类市场赚钱 |
| **每日** | 每日盈亏曲线，看稳定性 |

**用法**：跟单一周后回来看「按钱包」，把持续亏损的钱包停用或降权。

## 10. 多钱包分散跟单

同时跟多个钱包时，避免资金过度集中在某一个上。

进入 **🧺 组合跟单** 面板可查看分散情况：
- 每个钱包的权重、已用敞口、上限
- **集中度**指标：`最大单钱包盈亏绝对值 ÷ 总盈亏绝对值`
  - 🟢 ≤40% 健康
  - 🔵 40–60% 偏高
  - 🟡 >60% 过度集中，建议调整

**配置方式**（通过 API 或设置）：

| 参数 | 默认 | 说明 |
|---|---|---|
| `权重模式` | equal | `equal` 平均分配 / `manual` 手动权重 / `pnl` 按盈亏自动加权 |
| `单个钱包最大占比` | 0.6 | 任一钱包最多占总资金的 60%，超出部分自动截顶并让渡给其他钱包 |
| `组合总敞口` | 1000 USDC | 所有钱包合计的最大未平仓金额 |

配置保存在数据库 `config` 表的 `portfolio_allocation` 键，服务重启自动恢复。

## 11. 通知推送

进入 **🔧 设置** 面板的通知区，支持：

- **Telegram**（Bot Token + Chat ID）
- **钉钉**（Webhook）
- **企业微信**（Webhook）
- **邮件**（SMTP）

可分别开关：`新交易通知`、`新信号通知`、`执行结果通知`、`每日摘要`。
`每日摘要时间` 默认是 UTC 8 点（即北京时间 16 点）。

配好后点 **测试通知** 验证是否送达。

## 12. 参数配置说明

### 设置面板可调

| 分组 | 参数 | 默认 | 说明 |
|---|---|---|---|
| 执行 | 执行模式 | paper | paper 模拟 / live 真实 |
| 监控 | 轮询间隔 | 2 秒 | 数值越小检测越快，API 压力越大（最小 1 秒） |
| 监控 | 交易条数 | 50 | 每次轮询拉取最近多少条 |

## 14. 常见问题 FAQ

**Q1：双击 bat 提示 `Bundled Python not found`？**
A：`Python312/` 目录没有随文件夹一起拷贝。请确认项目目录下有 `Python312\python.exe`；若缺失，用 `0-install-deps.bat` 装系统 Python 后改用 `1-start-service.bat`。

**Q2：黑窗口一闪就没了？**
A：启动出错了但窗口自动关闭。Shift + 右键项目目录 → 「在此处打开 PowerShell 窗口」→ 执行 `Python312\python.exe run.py`，就能看到具体报错。

**Q3：页面打不开 / 一直在转圈？**
A：先看黑窗口有没有 `Uvicorn running on http://...`。没有说明服务没起来；有则检查端口是否被占用（换 `--port 9000` 试试）。

**Q4：添加了钱包但一直没交易？**
A：可能原因——① 代理没配，拉不到 Polymarket 数据（见下方黑窗口日志里的 `HTTP Request` 是否报错）；② 该钱包近期确实没交易；③ 钱包开关是停用状态。

**Q5：交易抓到了，但执行记录是空的？**
A：最常见是策略管道没以 MIRROR/REVERSE 结尾（只有执行类策略才产出信号），或管道处于停用状态。其次是被金额过滤过滤掉了——用第 4 节的**链路自检**注入一笔试试。

**Q6：执行记录里全是 `FAILED`？**
A：点开错误信息。最常见是「单笔金额 X 超过上限 100」——调大风控上限，或在策略里调小 `比例系数`。

**Q7：国内能用吗？**
A：Polymarket API 在国内网络环境下可能无法直连。在设置面板填代理地址（如 `http://127.0.0.1:7890`）即可。

**Q8：数据存在哪？会丢吗？**
A：全部存在项目目录 `data/trader.db`（SQLite）。备份这个文件即可迁移。删除它则所有历史清空（会重新自动创建）。

**Q9：能同时跟多少个钱包？**
A：没有硬限制，但轮询压力随钱包数线性增长。建议 10 个以内，或把轮询间隔调大。

**Q10：模拟（paper）模式的盈亏是真的吗？**
A：盈亏**按真实市场价计算**，但**资金是虚拟的**——不会真的花掉你的 USDC。建仓按 CLOB 真实盘口价，持有期按真实市价盯市，平仓按真实价配对结算（详见[第 5 章](#5-模拟盘的钱是怎么算的虚拟持仓盯市)）。

唯一与真实交易的差异：模拟撮合**假设你的单子能全额成交**，不考虑盘口深度不足和冲击成本。真实小额下单时这个差异很小，大额时会被放大。验证策略逻辑可靠，最终仍建议 live 小额度试水。

**Q11：虚拟持仓的「计价来源」显示 `unavailable` 怎么办？**
A：说明这一刻没取到真实市价（通常是网络/代理问题，或该市场已结算下架）。此时浮动盈亏按成本价计算（显示为 0），不会乱编数字。检查代理设置后点刷新即可恢复。
