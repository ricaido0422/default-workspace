## 0. 最快路径：只双击一个文件

### 日常就这样用

| 文件 | 作用 | 说明 |
|---|---|---|
| **`启动跟单控制台.bat`** | 一键启动网页控制台 | **中文说明，首选。** 自动装依赖、自动打开浏览器 |
| `START-HERE-双击我.bat` | 同上 | 英文说明版 |
| `运行测试.bat` | 跑 44 个单元测试 | 验证护栏没坏，只读不碰钱 |

第一次双击 `启动跟单控制台.bat` 时，它会先跑一次 `npm install`（需要一两分钟，只此一次）。之后每次启动都是秒开。

### 启动后能做什么

黑窗口打印完说明后，浏览器会自动打开 `http://127.0.0.1:8787`（如果没自动开，手输这个地址）。

在网页里你能做全部事情：

- **页面上方那个「运行模式」大开关**：DRY-RUN ⇄ LIVE。切 LIVE 要手输 `CONFIRM`，还会检查私钥 / 地址 / USDC 余额三项前置条件（详见第 9.7 节）
- **参数全部在网页上改**，改完点保存，下一轮轮询自动生效，不用重启
- **「测试网络」按钮**：确认能连上 Polymarket，顺带查 USDC 余额
- **「参数体检」按钮**：用他的历史单回测你的当前参数能跟到几笔
- **「启动 / 停止」按钮**：第一轮只记录不跟单（安全观察期）
- **自动守卫**：止损 / 止盈 / 单日熔断到线自动停（详见第 9 节）

> **关闭黑窗口 = 停止机器人。** 持仓账、已见单号已自动存盘，重启不会重复跟单。
> 控制台只监听 `127.0.0.1`，你电脑上没跑别的东西时，外网连不到它。

### 老 bat 文件去哪了

没删，都挪到了 `legacy\` 子目录里（避免和新的入口混在一起）。你现在只需要 `启动跟单控制台.bat`，但老的留着当备用：

| 老文件 | 作用 | 现状 |
|---|---|---|
| `legacy\1-检测网络.bat` | 只读探测，不下单 | 备用，等价于网页上的「测试网络」按钮 |
| `legacy\2-开始监控.bat` | 黑窗口 DRY-RUN 监控 | 备用，但**这是旧入口，不接自动守卫**（无退避、无熔断、不落盘），见第 9.6 节末尾 |
| `legacy\3-打开控制台.bat` | 网页控制台 | 备用，等价于 `启动跟单控制台.bat`，但不会自动 `npm install` |
| `legacy\4-运行测试.bat` | 44 个单元测试 | 备用，等价于 `运行测试.bat` |

> 想彻底关掉自动守卫的累计账目，删 `logs\console-state.json` 即可。正常情况下不用动它。

## 1. 3 分钟跑起来

```
D:\Users\Administrator\Documents\deepseek-harness\default-workspace\.dsh-switchman\probe-npm
```

### 1.2 装依赖

在这个目录里打开 `cmd` 或 PowerShell，执行：

```
npm install
```

看到 `added XX packages` 就成功了。

> **不需要这一步：** dry-run 模式零第三方依赖。[第 0 节](#0-最快路径只双击一个文件推荐)的 `.bat` 会帮你自动 `npm install`。
> 只有准备用真钱下单时才需要额外装两个包（见第 4.2 节）。

### 1.3 测网络（确认能连上 Polymarket）

```
npm run probe
```

正常输出长这样：

```
http://127.0.0.1:7897
...
http://127.0.0.1:7897

data-api /trades: HTTP 200 (164ms, 779 bytes)
gamma-api /markets: HTTP 200 (622ms, 6184 bytes)

--- 最近 10 笔 ---

  --  |      $6.67 | BUY  | Invictus Gaming @ 0.7 | LoL: ...
```

**看到三个 HTTP 200 就说明通了。** 这一步只读，不下单、不充钱。

**按 `Ctrl+C` 停止。**

## 2. 怎么自己改参数

**所有参数都在 `config.json` 这一个文件里。**

打开 `config.json`，每个字段下面都有一行 `_xxx_help` 中文注释，说明这个字段是干什么的、该填什么。改数字 → 保存 → 重新跑，就生效了。

```json
{
  "mode": "dry-run",
  "targetWallet": "0xbcc321b6336117432f4e9d2d28b20d8b6795ac9c",
  "minTradeUsd": 500,
  "maxTradeUsd": 5000,
  ...
}
```

**注意：** 在网页控制台里改参数点「保存」后，**下一轮轮询自动生效，不用重启**。只有换跟单对象、改下单金额、改仓位上限这三类会让机器人自动重启并清零累计账目（页面会提示）。

### 最容易踩的三个坑

| 坑 | 说明 |
|---|---|
| **数字别加引号** | `"minTradeUsd": 500` 对；`"minTradeUsd": "500"` 错（会被当成文字） |
| **注释字段以 `_` 开头** | `"_minTradeUsd_help": "..."` 是给人看的，程序会忽略，**别删也别改它的值** |
| **JSON 格式** | 最后一项后面不能有逗号；所有字符串用英文双引号 `"` |

### 最常用的两个字段

```
改 config.json 里的 maxTradeUsd 和 minTradeUsd
```

一个管「低于多少不跟」，一个管「高于多少不跟」。这两个调完，跟单风格就变了。

## 3. 每个参数是什么意思

所有参数都在 `config.json` 里，按小节分组，每组上面有一行 `_section_xxx` 中文标题。

### 3.1 运行模式

| 字段 | 默认值 | 说明 |
|---|---|---|
| `mode` | `dry-run` | `dry-run` = 只监控和打印，绝不下单（安全，先用这个跑几天）。`live` = 真实下单 |

> **日常请用网页控制台上方的「运行模式」大开关切换，不要手动改 `config.json`。** 开关会做三项安全检查，并要你手输 `CONFIRM`，手动改文件没有这些保护（见第 9.7 节）。

### 3.2 跟单对象

| 字段 | 默认值 | 说明 |
|---|---|---|
| `targetWallet` | `0xbcc321b6336117432f4e9d2d28b20d8b6795ac9c` | 要跟谁。去 [polymarket.com/leaderboard](https://polymarket.com/leaderboard) 找地址，把 `0x` 开头那串完整粘进来 |

当前跟的是 ColdBlooded：胜率 69%，盈亏比 1.79，活跃持仓只有 3 个（低频高信念型）。想换人用网页控制台的「交易员分析中心」，能直接看胜率、盈亏比、样本量，还能一键加入观察名单。

### 3.3 下单金额（CopyOdds 的两种做法）

| 字段 | 默认值 | 说明 |
|---|---|---|
| `sizingMode` | `fixed` | `fixed` = 每笔固定金额；`percent` = 按比例复制对方的仓位占比；`balancePercent` = 按自己本金比例 |
| `fixedOrderSizeUsd` | `3` | 每笔跟单固定下多少美元。`fixed` 模式才生效 |
| `percentScale` | `0.02` | `percent` / `balancePercent` 模式才生效。0.02 = 按对方下单金额的 2% 跟 |

三种模式的真实差别（用 30 美元本金举例）：

- **`fixed`**：每笔固定 $3，本金能撑 10 笔。**本金小必须用这个。**
- **`percent`**：对方下 $1000 你按 2% 跟 $20——但你只有 $30，且 Polymarket 最小下单额 $1，超过 30 美元就直接失败。
- **`balancePercent`**：按你自己本金的百分比下（比如每笔下本金的 50%），本金越下越少，会自动缩。

### 3.4 资金区间过滤（你要的双向过滤）

`minTradeUsd` / `maxTradeUsd` 两个字段配合，实现「只跟资金在一定范围内的订单」。详见第 8.5 节的板块过滤。

| 字段 | 默认值 | 说明 |
|---|---|---|
| `minTradeUsd` | `500` | 对方单笔成交额低于这个数就不跟。过滤小额试水单和噪音单 |
| `maxTradeUsd` | `0` | 对方单笔成交额高于这个数就不跟。`0` = 不设上限 |

> **为什么当前设 `0`（不设上限）：** ColdBlooded 是低频高信念型，大单往往就是最强信号，设上限反而可能砍掉他最值钱的下注。
> **2026-10-24 实测**他最近 20 笔单的资金分布：$500 ~ $3481.90 / $2662.00 / $887.00，普遍在 $3000 以上，没有异常大单。所以暂不设上限，先跑两周看分布再定。
> **如果换跟单对象，这一条要重新评估**（见下方 3.6 节）。

### 3.5 板块 / 赛事过滤（只跟某些板块）

`scopeMode` 三个值：`all`（不过滤）/ `whitelist`（只跟列表里的）/ `blacklist`（不跟列表里的）。

`scopeKeywords` 填英文，可填三级粒度：

- 板块：`esports`、`sports`、`politics`
- 赛事：`league-of-legends`、`dota-2`、`nba`
- 赛事阶段：`lol-worlds-2026`、`swiss-round-2`

**怎么知道该填什么：** 打开网页控制台 → 交易员分析中心 → 板块过滤 → 扫描他的板块，会列出他真实打过哪些标签。详见第 8.5 节。

| 字段 | 默认值 | 说明 |
|---|---|---|
| `scopeMode` | `all` | `all` 不过滤；`whitelist` 只跟；`blacklist` 拉黑 |
| `scopeKeywords` | `[]` | 英文逗号分隔，大小写随意 |

### 3.6 仓位上限（防一把亏光）

| 字段 | 默认值 | 说明 |
|---|---|---|
| `maxPerOrderUsd` | `3` | 单笔最多下多少美元。硬性保险，即使 sizing 算出来更大也压到这个数 |
| `maxPerMarketUsd` | `6` | 同一个市场（同一个问题）最多累计下多少美元。防止在同一个判断上反复加码 |
| `maxTotalInvestedUsd` | `15` | 同时在手的钱最多多少美元。30 本金的 50%，留一半现金 |
| `minMarketVolumeUsd` | `50000` | 市场成交量低于这个数就不跟。过滤冷门到没人玩的盘 |

> **这个下限要注意**
> 2026-10-24 看 ColdBlooded 的下单：$3481 / $2662 / $887 都押在 LoL 上，但该市场总成交量只有 **$36,453**，低于 $50,000。如果照搬这个数，他最好的几笔全会被过滤掉。
> **建议：** 改成 `$20000`，或者设 `0`（不过滤）。设了 $50,000 的结果就是所有单都显示 `DIM` 被跳过。

### 3.7 自动守卫（止损 / 止盈 / 单日熔断）

| 字段 | 默认值 | 说明 |
|---|---|---|
| `stopLossTotalUsd` | `-9` | 总浮亏到这个数就自动停机。30 本金的 30%。**必须填负数** |
| `takeProfitTotalUsd` | `15` | 总浮盈到这个数就自动停机。30 本金翻倍，先落袋。**必须填正数** |
| `maxDailyLossUsd` | `5` | 今天累计真实亏到这个数就熔断停机，第二天自动恢复。`0` = 不启用 |
| `autoFlattenOnStop` | `false` | 触线时是否连带市价清仓。默认 `false`（原因见第 9.2 节） |
| `minSellPrice` | `0.02` | `autoFlattenOnStop=true` 时才生效。低于这个价就不卖 |
| `riskCheckEveryRounds` | `5` | 每隔几轮检查一次浮亏是否触线。5 轮 × 60 秒 = 5 分钟一次 |
| `pollIntervalSeconds` | `60` | 每隔多少秒检查一次对方有没有新交易。60 秒足够 |

详细行为和区别见[第 9 节](#9-自动执行与风控)。

### 3.8 下单方式

| 字段 | 默认值 | 说明 |
|---|---|---|
| `orderType` | `FOK` | `FOK` = 全部成交否则全撤（跟单首选，避免半仓卡住）。备选 `FAK`（能成多少成多少）、`GTC`（限价挂单等成交） |

### 3.9 只有 `live` 才需要的钱包字段

| 字段 | 说明 |
|---|---|
| `privateKey` | Base 网络钱包的私钥（`0x` 开头 64 位）。**只存在你自己电脑上，绝不外发** |
| `rpcUrl` | Base 链节点。默认官方公共节点，慢可换付费节点 |
| `funderAddress` | 你的 USDC 充值地址（Base 网络）：`0x1279333686e1766Efc417acD55547E772EA7328`。钱从这里出 |
| `signatureType` | `0` = 普通 EOA 钱包（交易所直提到 Base 的私钥钱包）。`1` = Magic/邮箱登录钱包。`2` = 浏览器插件代理钱包。多数人用 `0` |

### 3.10 日志

| 字段 | 默认值 | 说明 |
|---|---|---|
| `logToFile` | `true` | 把日志写到 `logs\` 目录，按天分文件 |
| `verbose` | `true` | 打印被过滤掉的单子。**推荐 `true`**，能看到机器人为什么没跟，方便调参数 |

## 4. 怎么用真钱下单

> **前提：先用 dry-run 模式跑至少 3 天，确认它能正常跟到单、过滤逻辑符合预期，再考虑这一步。**

### 4.1 准备三样东西

- USDC 存到 Base 网络地址 `0x1279333686e1766Efc417acD55547E772EA7328`
- 本金约 $30
- **要一点 ETH on Base 当 gas**（约 $1 就够）

> **必须走 Base 网络，不要用以太坊主网。** 主网桥接的 gas 可能 $5–20，会直接吃掉你本金的 17%–67%。在 [basescan.org](https://basescan.org) 上能查到 USDC 余额是否到账。
> **从交易所提现时，网络选 Base**（有的交易所叫 "Base" 或 "Coinbase Base Chain"），不要选 Ethereum / Arbitrum / Optimism。

### 4.2 装真下单用的两个包

```
npm install @polymarket/clob-client ethers@6
```

**必须是 `ethers@6`，不要装 ethers@5**（两版 API 不兼容，会用不了）。

### 4.3 填私钥

在 `config.json` 里改：

```json
"mode": "live",
"privateKey": "0x64位十六进制私钥",
```

> **更推荐在网页控制台里填**，私钥输入框在「钱包设置」区，保存后不会显示在页面上，也不会出现在任何日志里（日志里会打成 `0x****(私钥已隐藏)****`）。

### 4.4 先小金额试一笔

把单笔金额降到 $1：

```json
"fixedOrderSizeUsd": 1,
"maxPerOrderUsd": 1
```

原来设的是 `3`。先用 $1 跑通整个流程（能看到下单成功、能在 Polymarket 网站上看到持仓），再调回 `3`。

### 4.5 启动

```
npm start
```

> `package.json` 里 `start` 等价于 `node src/index.mjs`。日常还是推荐用网页控制台，它有自动守卫。

### 4.6 想退回安全模式

把 `mode` 改回 `"dry-run"` 就行，或者直接点网页上方的模式开关切回 DRY-RUN（切回不需要确认，点一下就生效）。

## 5. 每天怎么用

### 5.1 看日志

日志按天存在 `logs\` 目录，例如 `logs\2026-10-24.log`。

### 5.2 日志级别速查

| 标记 | 含义 | 要不要管 |
|---|---|---|
| `OK` | 正常 | 正常跟单 / 正常操作 |
| `INFO` | 提示 | 一般信息 |
| `DIM` | 被过滤掉的单子 | 正常（说明过滤规则在工作）。只有 `verbose` 为 `true` 时才打 |
| `ERR` | 错误 | 要处理 |

### 5.3 看懂「跳过」的原因

```
 | $120.00 BUY | ... | 因 $120.00 < $500.00 不跟
```

这行的意思是：对方下了一笔 $120 的单，但你的 `minTradeUsd` 是 $500，所以不跟。**这是正常的。** 想跟这种单就把 `config.json` 里的 `minTradeUsd` 调低。

### 5.4 关于 dry-run 的金额

dry-run 日志里显示的 "$3.00" 是**假设值**——它按你的参数算「如果真下单会下多少」，并不会真的扣钱。想验证金额算得对不对，去 Polymarket 网站看对方实际下了多少，对比一下。

## 6. 排错速查

### 6.1 连不上（timeout / connect timeout）

**现象：** `fetch failed` 或 `UND_ERR_CONNECT_TIMEOUT`。

**原因：** 2026-10-24 实测 polymarket.com 在本机需要走本地代理（Node.js 的 `fetch` **不走系统代理**）。可用的代理端口：`7897` / `7890` / `10809` / `10808` / `1080` / `8080` / `7891` / `2080` / `33210`。

通了之后输出长这样：

```
http://127.0.0.1:7897
data-api /trades: HTTP 200 (164ms, 779 bytes)
```

**解决办法：**

1. **先确认你的代理客户端在跑**，且 polymarket.com 能通
2. **指定代理端口**（PowerShell）：
   ```powershell
   $env:HTTPS_PROXY="http://127.0.0.1:7897"; npm run dryrun
   ```
   或者在 `cmd` 里：
   ```
   set HTTPS_PROXY=http://127.0.0.1:7897
   set NODE_USE_ENV_PROXY=1
   npm run dryrun
   ```
   > `NODE_USE_ENV_PROXY=1` **必须加**。Node v26 的 `fetch` 不会自动读 `HTTPS_PROXY`，加了这个变量才会走。
3. **换个端口试**，上面列了 9 个常见端口
4. **最后手段：** 换 DNS 到 `8.8.8.8` 或 `1.1.1.1`

### 6.2 `npm install` 失败

```
npm config set registry https://registry.npmjs.org/
npm cache clean --force
```

如果 `dry-run` 模式下还提示缺依赖，是因为 `npm install` 没跑完就退了——重跑一次 `npm run dryrun` 即可。

### 6.3 `live` 模式提示缺依赖

```
npm install @polymarket/clob-client ethers@6
```

### 6.4 提示余额不足（"not enough balance / allowance"）

先确认 USDC 真的到账了：去 [basescan.org](https://basescan.org) 查你的 Base 地址。

最常见的原因是**网络选错了**——USDC 在以太坊主网上，没转到 Base。见第 4.1 节。

其次，Polymarket 部分市场**单笔最少要 $1**，下 $0.50 必然被拒。

### 6.5 下单被拒的各种报错

网页控制台会显示 `ERR | ... | <原因>`：

| 报错 | 含义 | 怎么办 |
|---|---|---|
| `not enough balance / allowance` | USDC 不够或未授权 | 查 basescan 确认到账；确认是 Base 网络；Polymarket 部分盘最少 $1 |
| `invalid amount` | 金额不合法 | 把 `fixedOrderSizeUsd` 改成 `1` 或更大 |
| `market is closed` | 市场已关闭 | 正常，跳过即可 |
| `no match` | 限价单没成交 | `OK` 级别，不影响 |

### 6.6 想清空历史记录重新开始

`logs/state.json` 里存了「已经见过哪些单号」和「累计投了多少」。

**谨慎操作：** 删掉 `logs\state.json` 会让机器人忘记跟过谁，可能重复跟单。同时它也会把 `totalInvested` 累计账清回 0，导致仓位上限失效——**确认你手上没有真实持仓时再动它。**

## 7. 安全红线

1. **私钥只在这台电脑上。** 截图、发人、贴群里，任何一样都等于把钱送人。
2. **`config.json` 里有你的真地址。** 分享文件前先删掉 `privateKey` 和 `funderAddress` 字段。
3. **先用 dry-run 跑满 3 天**，确认跟单逻辑正常再碰真钱。
4. **30 U 是学费+平台测试费。** 核心产出是三件事：滑点实测、平台可信度、心理承受度。不要指望靠它赚钱。
5. **止损设在 -$9，正好本金的 30%。** 到了就停，别改大——改大就是把风险敞口放大。
6. **止盈 +$15，本金翻倍。** 到了先落袋，用利润继续滚，本金拿回来。
7. **不要用以太坊主网桥接，gas 会吃掉本金 17%–67%。** 一定走 Base。
8. **不要跟 HomeRunHazard。** 胜率 51%（和抛硬币持平）、盈亏比 1.05、同时押 611 个市场、45,775 个市场全品类撒网——这种没法复制，且他的收益来自极小部分极端单。

### 安全机制（代码里已经做了）

| 机制 | 具体行为 |
|---|---|
| **私钥打码** | 日志里 `0x` + 64 位十六进制一律打成 `0x****(私钥已隐藏)****`，console 和文件两边都打 |
| **只监听本机** | 控制台只听 `127.0.0.1:8787`，外网连不到 |
| **拦跨站请求** | 所有 POST 都检查 `Origin` 头，且 `content-type` 必须是 `application/json`，否则返回 `403` |
| **防跟错人** | `targetWallet` 和 `funderAddress` 不允许填成同一个地址（自己跟自己是死循环） |
| **单日熔断** | `maxDailyLossUsd` 到线当天停止开新仓，第二天自动恢复 |

另外：`percent` 模式下 Polymarket 有 **$1 最小下单额**，本金太小会用不了——这是平台规则，不是 bug。

## 8. 交易员分析中心

**这是网页控制台上的一个选项卡，用来选跟单对象、看板块分布、维护观察名单。**

### 8.1 观察名单

存在 `watchlist.json` 里。加入规则：

- 胜率 ≥ 60%
- 盈亏比 ≥ 1.5
- 样本量足够（不是只跑了几十单的运气型）
- 会出现在 `targetWallet` 里

> 观察名单只是候选池，**不等于就换人**。换人要重跑第 3.6 节的参数评估。

### 8.2 能看到什么

每个候选交易员会算出来：胜率 / 盈亏比 / 盈利因子 / 已实现盈亏 / 活跃持仓数 / 总单数 / 最近 30 天盈亏 / 平均单笔 / 最大单笔 / 持仓市场数。

### 8.3 用 $30 本金跟单的真实预期

拿当前对象 ColdBlooded 举例：

```
假如他下 $2930、你只有 $30  →  按 2% 算是 $58.66，超出本金
若改成每笔 $3               →  $879 的本金对应 46001 单？不成立
实际结果：$15.00 是你的仓位上限，最多占本金 50%
```

换句话说：**$30 本金不可能真正"复制"一个下 $3000 单的人。** 你能做到的是「他看多的时候你也押一点，方向对就赚比例小但方向对的钱」。这正是 `maxTotalInvestedUsd: 15` 存在的原因。

### 8.4 一键加入观察名单

在分析表格里点一下就能加/移除，存在 `watchlist.json`。

### 8.5 板块 / 赛事过滤

比如你只想跟他的英雄联盟（LoL）相关下单。

**取数的两条路：**

```
/markets?condition_ids=X   → 只有 seriesSlug（如 league-of-legends），没有 tags
/events?slug=Y             → 这里才有 tags
```

所以必须先查 `/markets` 拿到 `seriesSlug`，**再查 `/events` 才能拿到板块标签**。标签结果会缓存 10 分钟。

**ColdBlooded 的标签分布（实测）：**

| 标签 | 含义 | ColdBlooded 命中 |
|---|---|---|
| `esports` | 电竞大类 | 60 笔 |
| `games` | 游戏类 | 60 笔 |
| `sports` | 体育类 | 60 笔 |
| `league-of-legends` | 英雄联盟 | 51 笔 |
| `dota-2` | Dota 2 | 9 笔 |

一个市场常同时挂多个标签（同一场 LoL 比赛会同时带 `esports` + `league-of-legends`）。

**只跟 LoL 就这样填：**

```
scopeMode: whitelist
scopeKeywords: esports, league-of-legends, lol-worlds-2026
```

**三种模式：**

- `all`：不过滤（默认）
- `whitelist`：只跟 `scopeKeywords` 里的板块
- `blacklist`：不跟 `scopeKeywords` 里的板块

**写法规则：**

- 长度小于 2 个字符的关键词会被拒绝（防止误填一个字把全部过滤掉）
- 大小写随意，`League of Legends` = `league-of-legends`
- `-` 和 `_` 等价，空格也等价（`league of legends` = `league-of-legends`）

**`whitelist` 存空列表会被拒绝保存**——空白名单意味着"什么都不跟"，与其静默不跟单，不如直接报错让你发现。

### 8.6 跟单对象对比表（历史结论，别重算）

数据来自 Polymarket 的 `/closed-positions`，**按 `realizedPnl` 排序取前 N 名**：

| 交易员 | 页面显示 | 复算结果 | 样本量 |
|---|---|---|---|
| ColdBlooded | 胜率 68.5% / PF 1.75 | **胜率 68.5% / PF 1.75** | 270 笔 |
| Smallcoins | 胜率 79.0% / PF 5.76 | **79.0% / PF 5.76** | 1855 笔 |

## 9. 自动执行与风控

**这一节是全项目最重要的部分。** 前面所有功能都是"能看、能配"，这一节是"到线自己停、失败自己退避、断电不重复跟单"。

### 9.1 三条线各管一件事

| 线 | config 字段 | 看什么 | 默认值 | 说明 |
|---|---|---|---|---|
| 止损 | `stopLossTotalUsd` | **总浮亏** | `-9` | 亏到 $9 自动停机（本金 30%） |
| 止盈 | `takeProfitTotalUsd` | **总浮盈** | `15` | 赚到 $15 自动停机（本金翻倍） |
| 单日熔断 | `maxDailyLossUsd` | **当天真实亏出去的** | `5` | 今天亏 $5 当天停止开新仓，第二天自动恢复 |

三者的区别很关键：

- **止损看浮亏**：账面浮动亏损，会来回震荡，可能这轮 -$8 下轮 +$3
- **止盈看浮盈**：同理，账面浮动盈利
- **熔断看"今天真实亏出去的钱"**：已实现亏损，只累加不减少，防的是"今天手气背，别再下了"

### 9.2 触发后会发生什么、不会发生什么

**会发生：**

- 立即停止开新仓（机器人进入 halted 状态）
- 停机原因写进 `logs\console-state.json`，网页健康面板显示
- 日志记一条 `ERR` 说明是哪条线触发的、当时账面是多少

**不会发生：**

- **不会替你卖出持仓。** 默认 `autoFlattenOnStop: false`
  原因：冷门盘市价抛售的滑点常常比止损线还大，本来 -$9 的账面亏损，市价砸出去可能变 -$14，反而更亏。放着等结算常常更划算。
- 不会清空你的已见单号、累计账目。重启后这些都在，不会重复跟单。

**如果你想触线时自动清仓：**

```json
"autoFlattenOnStop": true,
"minSellPrice": 0.02
```

`minSellPrice: 0.02` 表示低于 2 分不贱卖，防止把还有希望的仓位按垃圾价抛掉。

### 9.3 解除停机的故意摩擦

停机后想重新启动，必须点网页上的「解除风险停机」按钮，**不能一键绕过**。

设计意图：到线说明当前策略或当前对象有问题，逼你停下来看清楚原因，而不是无脑重启继续亏。

解除时**不会**清空 `perMarket`、`seen`、累计账——那是真金白银的账，清了会导致重复跟单。

### 9.4 失败退避表

网络或接口连续失败时会自动拉长轮询间隔，不会一直撞墙：

| 连续失败次数 | 下次等待 |
|---|---|
| 1 | 60 秒（正常间隔） |
| 2 | 120 秒 |
| 3 | 240 秒 |
| 4 | 480 秒 |
| 5+ | 900 秒（15 分钟） |
| **连续 6 次** | **自动停机**，日志说明原因 |

恢复后会自动回到 60 秒，并打一条「网络恢复」。

### 9.5 健康面板

网页控制台里有一块实时状态区，显示四组信息：

- **连续失败次数**：正常显示「网络正常 / N 秒后重试」；连续失败时变黄并显示倒计时
- **上次轮询耗时**：超过 10 秒会变黄（说明接口在拖）
- **浮亏进度条**：在止损线和止盈线之间标出当前浮盈/浮亏位置，附带数据来源（live = Polymarket 实际持仓，dry-run = 纸面重估）
- **今日已亏 vs 熔断线**：例如「今日已亏 $1.20 / 熔断线 $5.00」

### 9.6 断电能保住什么

`perMarket`（每个市场已投多少）、`totalInvested`（总投入）、已见单号都存在 `logs\console-state.json` 里，最多保留 2000 条已见单号、200 条纸面持仓。断电重启后：

- 不会重复跟同一笔单
- 仓位上限继续生效
- dry-run 的纸面持仓继续显示（按 $X 这样的格式）

**断电保不住的是：** 这一轮轮询跑到一半被强杀，那半轮的状态。这是任何系统都无法避免的窗口期。

> **注意 `legacy\2-开始监控.bat` 这个旧入口：** 它直接跑 `src\index.mjs`，不接退避、不接熔断、不落盘（每 30 轮才打印一次对方盈亏作参考，不会停机）。**要自动执行，请用网页控制台。**

### 9.7 运行模式开关：为什么不是一个下拉框

因为 DRY-RUN → LIVE 这个动作值得两道摩擦：

1. **整行醒目的大按钮**，不是藏在表单里的下拉框
2. **必须手输 `CONFIRM`**，输错或取消都停在 DRY-RUN

切到 LIVE 前还会列三项前置条件，缺哪项标红：

- 已填私钥（`config.json` 里有）
- 充值地址是 `0x` + 40 位十六进制
- 钱包里有 USDC on Base（查不到余额会提示）

切回 DRY-RUN 不需要确认——变安全永远不该有摩擦。

> 顺带说明：`privateKey` 在「热更新检测」列表里，所以你在网页上填一次私钥，会被记成一次参数变更。这是正常现象，不是 bug。

### 9.8 测试与私钥打码

`运行测试.bat` 跑 44 个单元测试，覆盖：

- 大写 `0X` 和小写 `0x` 开头的私钥都能打码（`util.mjs` 和 `guard.mjs` 用同一套正则）
- Origin 校验：无 Origin + JSON 放行；外站 Origin 一律拒（`403`）
- 风控停机 / 退避重试 / 换跟单对象清账 / 跨日熔断重置

改完 `config.json` 后跑一次测试，确认护栏没坏。
